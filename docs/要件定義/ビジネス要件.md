# ビジネス要件（Business Requirements）

## 概要

本プロジェクトの目的は、セキュリティ制約によりクラウドサービスを利用できない環境でも、  
生成AIを安全かつ効果的に活用できるようにすることである。  
具体的には、オフラインで動作する文書検索・要約システム（文書RAG）をデスクトップアプリとして提供し、  
AI導入が困難だった組織・業務現場の業務効率化を実現する。

---

## 目的と狙い

- インターネット接続が制限された環境でも生成AIを活用可能にする。  
- 機密情報を外部に送信することなく、安全にAIを業務利用できる環境を提供する。  
- 文書検索・要約・質問応答などをAIが代行し、知的労働の負担を軽減する。  
- AI導入が難しかった分野（医療、法務、金融、行政、教育など）に実運用可能なソリューションを提供する。  
- オフラインAIの標準プラットフォームとしての基盤を確立する。

---

## ビジネス課題

| 課題 | 説明 |
|------|------|
| セキュリティ要件によるAI利用制限 | 機密データを外部APIやクラウドに送信できないため、生成AIの導入が進まない。 |
| オンライン依存型AIのリスク | ChatGPTなどの高性能AIはオンライン前提であり、情報漏洩リスクがある。 |
| 文書管理業務の非効率性 | 膨大な文書から必要情報を探す作業が人手に依存しており、時間的コストが大きい。 |
| 日本語RAGの精度課題 | 既存の英語ベースRAGモデルでは、日本語文書の精度が不十分。 |
| ITリテラシー格差 | 現場職員でも扱える操作性を備えたAIツールが少ない。 |

---

## 解決方針

- 完全オフライン動作を実現し、ネットワーク遮断環境でも利用可能とする。  
- ローカル環境内での文書解析・ベクトル検索・生成を一貫して処理する設計とする。  
- ユーザー自身が利用するLLM（gguf形式）を選択・アップロードできる柔軟な構成とする。  
- 直感的なデスクトップUIを備え、専門知識を持たない利用者でも操作可能にする。  
- 医療・法務・教育など、各分野での実証と最適化を進め、社会的信頼性を確立する。

## ターゲットユーザーと市場想定

| ターゲット | 主な利用目的 | 導入背景 |
|-------------|----------------|-----------|
| 医療機関 | 診療記録・症例情報の要約と検索 | ネットワーク制限・個人情報保護の必要性 |
| 法律事務所・企業法務部門 | 契約書・訴訟資料の検索・比較 | 機密保持義務とデータ漏洩リスク |
| 金融機関 | 内部規定・報告書・審査文書の整理 | 顧客情報保護・コンプライアンス要求 |
| 教育機関 | 教材・成績・レポートの分析 | クラウド利用制限と個人情報保護 |
| 行政・自治体 | 各種行政文書の検索・分類 | 内部ネットワークでの情報統制 |
| 製造・研究開発部門 | 技術資料・実験データの整理 | 社外秘データの安全な知識活用 |

## 提供価値（Value Proposition）

- クラウドを使用しない安心設計により、**情報漏洩リスクを根本的に排除**  
- 社内文書をAIが直接読解し、**ナレッジ検索を自動化**  
- データを「守る」と同時に「活かす」仕組みを提供  
- AI導入に関する法務・セキュリティ上の障壁を解消  
- 日本語特化モデルにより、**高精度かつ現場向きのRAG回答** を実現

## 想定リスクと対応方針

| リスク | 対応方針 |
|---------|-----------|
| 高スペック環境でしか動作しない可能性 | 軽量モデル提供と最適化済みパッケージを同梱 |
| モデル精度のばらつき | テスト済み推奨モデルを同梱、ユーザーアップロードをオプション化 |
| 日本語RAGの誤回答（ハルシネーション） | コンテキスト制御とスコア閾値による回答制御を導入 |
| 運用サポート負担 | ドキュメント整備、FAQ・自動アップデートモジュールの提供 |

## 要約

本プロジェクトは、  
「AIを安全に、どの現場でも使えるようにする」という社会的課題を解決し、  
クラウドに依存しない生成AIインフラを構築することを目的とする。  

セキュリティを最優先に設計された本アプリにより、  
情報漏洩の懸念を持つ業界・組織にもAI活用の道を開き、  
日本の業務現場における生成AIの安全な普及を推進する。
