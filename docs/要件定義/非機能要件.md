# 🧩 非機能要件定義書  
**プロジェクト名：LocalSafeAI（ローカルセーフエーアイ）**

---

## 1. 性能・スループット要件

| 項目 | 要件内容 | 備考 |
|------|-----------|------|
| 起動時間 | アプリ起動から操作可能状態になるまで **30秒以内** | モデルロードを含む |
| 文書検索応答時間 | 1問あたり **10秒以内（CPU）／5秒以内（GPU）** | ベクトルDBに1万件登録時を想定 |
| 文書インデックス化速度 | 1文書（PDF約50ページ）を **30秒以内** に処理 | embedding処理含む |
| 同時処理 | 1ユーザーあたり同時1クエリ処理 | マルチスレッドで応答最適化 |
| メモリ使用量 | 推奨環境で **RAM 16GB** | LLM・Faiss・UI含む |

### 文書アップロード制約（閾値）

| 項目 | 要件内容 | 備考 |
|------|-----------|------|
| ファイル形式 | PDF, DOCX, TXT, CSV | 構造化・非構造化問わず |
| 1ファイルの最大サイズ | **10MB以内** | テキスト化・embedding性能を考慮 |
| 登録可能ファイル数 | **制限なし** | PostgreSQL + Faiss性能上の上限 |
| 総データ容量 | **任意設定（20GB-100GB）**（テキスト化後） | ローカルDB容量目安 |
| 非テキスト要素 | 画像・表などはOCR/変換対象外 | テキスト抽出失敗時はスキップ |
| 同時アップロード | **100MB以内** | サイズに収まれば何件でも可能 |

### LLMモデルアップロード制約

| 項目 | 要件内容 | 備考 |
|------|-----------|------|
| 対応形式 | **gguf形式（llama.cpp互換）** のみ対応 | 他形式はアップロード時に警告を出して拒否 |
| 最大ファイルサイズ | **50GB以内（1ファイルあたり）** | VRAM・RAM使用量を考慮した制限値 |
| 登録可能モデル数 | **最大10件** | ロード時間・ディスク容量を考慮 |
| 同時ロード数 | **1件（選択モデルのみ）** | メモリ衝突防止 |
| 推奨モデルサイズ | 7-8Bパラメータ（中型モデル） | CPU/GPU共用環境を想定 |
| 保存先 | アプリディレクトリ内の `models/` フォルダ |
| アップロード権限 | **管理者のみ実行可** | 一般ユーザーは切替のみ可 |
| エラー処理 | モデル読み込み失敗時はログ出力 |
| 設定変更 | モデルパスやロード設定は `config.yaml` に保存・編集可能 |

## 2. 可用性・信頼性

| 項目 | 要件内容 |
|------|-----------|
| システム稼働率 | ローカル環境で常時稼働を前提（停止要因はユーザー操作のみ） |
| 障害復旧 | 異常終了時に自動的に最後のセッション情報を復元可能 |
| データ保全 | 文書DB・ベクトルDBを冗長バックアップ（ユーザーディレクトリ配下） |
| エラーログ | すべての例外を `log/` ディレクトリに自動保存し、管理者が参照可能 |

---

## 3. セキュリティ要件

| 区分 | 要件内容 |
|------|-----------|
| 外部通信 | ネットワーク接続を行わない。通信を一切発生させない。 |
| データ保存 | 文書・ベクトル・設定情報を **AES-256暗号化** でローカル保存。 |
| 認証・認可 | 一般ユーザー／管理者の二段階権限管理。 |
| モデル管理 | LLMモデルのアップロードは管理者権限のみ許可。 |
| ログ管理 | 操作ログを改ざん防止形式で記録。 |
| 監査対応 | 第三者機関のセキュリティ監査に耐えうる構成。 |

---

## 4. 保守・運用性

| 項目 | 要件内容 |
|------|-----------|
| アップデート方式 | オフライン差分アップデートパッケージを提供。 |
| 設定管理 | 設定ファイル（JSON/YAML）によりバックアップ可能。 |
| ログ閲覧 | 管理者画面から動作・エラーログを閲覧可能。 |
| モデル切替 | 管理者UIでワンクリック切替可能。 |
| ドキュメント | 操作マニュアル・FAQをアプリ内に同梱。 |

## 7. テスト要件

| テスト項目 | 目的 | 成果基準 |
|-------------|------|-----------|
| 機能テスト | 各機能が仕様通り動作すること | 合格率100% |
| 負荷テスト | 同時処理・大量文書下での応答時間検証 | 応答時間閾値以内維持 |
| セキュリティテスト | 外部通信・アクセス漏洩の有無を確認 | 通信検出ゼロ |
| 回帰テスト | バージョン更新後も既存機能が正常動作すること | 既知不具合なし |

## 9. 環境・導入要件

| 項目 | 要件内容 |
|------|-----------|
| 最低動作環境 | CPU: 4コア / RAM: 8GB / SSD空き: 10GB |
| 推奨環境 | CPU: 8コア / RAM: 16GB / GPU: 8GB VRAM |

| ネットワーク | 初回セットアップから完全オフライン動作可能 |

---

## 10. 非機能要件まとめ（要約）

> **LocalSafeAI** は、  
> 「**完全オフライン・安全・高速・使いやすい**」を非機能目標とし、  
> セキュリティ・性能・操作性のすべてで公共機関・医療機関レベルの品質基準を満たす。
> 基本は一般的なパソコンの性能で動くモデルを使用することを想定している
